# kitchen-daylight-docker

Local development and test environment for the Kitchen Daylight restaurant app: PostgreSQL with PostGIS, Mailpit, an S3-compatible emulator, an optional API and Caddy, and a throw-away end-to-end test stack.

This repository is for **local development and testing only**. It is **never deployed**, and it holds no secrets and no real data.

> **Red flag:** every credential in this repository is a local placeholder. Never reuse any of them outside a local machine.

## Status

**Documentation only until phase 1 is done.** The documents describe the plan and the work proceeds task by task. So far only the `postgres` service exists; the full quick start and the `scripts/up.sh` wrapper come later.

Start with [docs/README.md](docs/README.md).

## Requirements

- Docker Engine 20.10.23 or newer and Docker Compose 2.24.1 or newer (`docker compose`, not `docker-compose`); bash 3.2 or newer.
- **Several GB of free disk space for Docker** (on Docker Desktop: the disk image). The S3 emulator needs free space for its volumes; with an almost full disk, object uploads fail with HTTP 500 and the container needs a hard kill to stop, while bucket creation still looks fine.

## Environment files

Three files configure the stack. Only `.env` and `.env.test` are generated.

| File | In git | What it is |
|---|---|---|
| `versions.env` | yes | Pinned image references (tag and digest). Edit it only to change a version |
| `.env.example` | yes | Template with the slot 2 values and placeholder passwords |
| `.env`, `.env.test` | no (ignored) | Generated by `scripts/init-env.sh`: dev stack and test stack (ports +5, project `kd-docker-test`) |

Create them once, after cloning:

```bash
scripts/init-env.sh        # slot 2 (default)
scripts/init-env.sh 3      # another slot, every port is base + slot x 10
scripts/init-env.sh 2 --force   # overwrite existing .env and .env.test
```

- Never copy `.env.example` by hand: the script computes the ports.
- The script refuses (exit 3) when `.env` or `.env.test` already exists without `--force`, or when a port of the slot is already listening. Pick another slot or stop the stack that uses the port.
- The generated files hold placeholder credentials (`CHANGE_ME_LOCAL`). Keep them local.

### Running Compose by hand

Plain `docker compose` reads only `.env`, not `versions.env`, so the image variables stay empty and the build fails with `base name should not be blank`. Always pass both files:

```bash
dc() { docker compose --env-file .env --env-file versions.env "$@"; }

dc up -d --build --wait --wait-timeout 120 postgres   # build, start, wait until healthy
dc exec -T postgres psql -U kd_migrator -d kd_dev -c "\dx"
dc down                                               # keeps the data volume
dc down -v                                            # also deletes the data volume (resets the database)
```

- `--wait` matters: the database is usable only after the init scripts have finished (first start only). Stopping the container during that phase can leave a half-initialised volume; if that happens, run `dc down -v` and start again.
- The scripts in `scripts/` (added in phase 1) pass these files for you: `scripts/up.sh` starts the stack, `scripts/status.sh` shows it, `scripts/down.sh` stops it (data kept).
- The postgres image is built only when it is missing. After changing `postgres/Dockerfile` or the pins in `versions.env`, run `scripts/up.sh --build` (it recreates the database container). Do not use `--build` on every start: each build gives the image a new digest and Compose recreates the container.
